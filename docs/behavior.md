# Поведение и происхождение этапов

Актуальная реализация основана на последнем сохранённом варианте банка. Ранние копии убраны из `main`; их исходники доступны в тегах.

| Сценарий | Актуальная реализация |
|---|---|
| Пользователи и счета, хранение PostgreSQL | Сохранены; создание клиента теперь включает учётную запись |
| Друзья и комиссии 0/3/10% | Сохранены |
| Пополнение, снятие, перевод и история | Сохранены; добавлены валидация и блокировки |
| REST, фильтры пользователей и операций, OpenAPI | Сохранены |
| Роли Admin/Client и закрытая регистрация | Сохранены; устранены ошибки проверок владельца |
| Котировки RabbitMQ и конвертация баланса | Сохранены; добавлены срок актуальности и порядок событий |
| Консольный интерфейс Hibernate-варианта | Доступен в `course/lab-2`; актуальный интерфейс — REST |

Изменения контрактов: существующие маршруты и поля запросов сохранены. Клиент может использовать маршрут списка собственных счетов; для чужих возвращается 403. `money` обязателен и положителен, допускает до двух знаков после запятой. Перевод на тот же счёт возвращает 400. Списание комиссии округляется `HALF_UP` до двух знаков. Проверки UUID выполняются по значению.

Коды валют — три заглавные латинские буквы; `RUB` не требует обращения к поставщику. Внутренний `RatesResponse` содержит время котировки; версии обоих сервисов следует обновлять вместе. Баланс конвертируется с пятью знаками (`HALF_UP`), как в исходном API.

SQL создаёт новую схему. Применение её к существующей установке — отдельная задача; запуск не выполняет автоматические миграции.
